# 多形象选择设计

## 目标

为 Android 语音聊天应用增加四个可选择的虚拟形象：可爱小女孩、可爱小男孩、青年美女、青年俊男，同时保留现有形象。用户可以在首次设置和设置页中选择形象；选择与聊天风格相互独立，并在下一次会话开始时生效。

## 已确认的产品决策

- “新增 3 个”按列出的四个名称解释为新增 4 个形象。
- 现有形象保留，作为默认和资源缺失时的回退。
- 形象与“孙辈型 / 老朋友型”聊天风格独立保存。
- 首次启动先选择聊天风格并完成已有身份注册，再选择形象。
- 日常从现有设置入口进入同一套设置页；设置页分为聊天风格和形象两个分区。
- 保存形象后不重建当前会话；下一次会话加载新形象。
- 主标题使用用户给出的四个名称；副标题只描述气质，不写入模型指令。

## 方案

采用本地头像目录和 Flutter 偏好存储。头像选择不进入网关协议、角色提示词、记忆账本或声音配置。`DeviceIdentity` 继续负责设备身份和聊天风格；头像 id 由同一设备上的安全凭据存储单独保存。

头像目录提供稳定的 id、中文文案和 WebView 相对资源路径。`AvatarPage` 读取已保存的 id，将目录中的路径传给 WebView 配置。`avatar-core` 在边界校验配置，只接受目录白名单中的相对路径；未知、空值或加载失败时使用现有默认模型，保证老安装和缺失资源仍可启动。

模型文件放在 `avatar-core/public/avatars/`，由现有 Web 构建脚本复制到 `app/assets/web/avatars/`。当前仓库只有本地忽略的 `avatar.glb`，因此第一阶段先完成目录、选择链路和回退；四个真实 GLB 文件到位后只需替换资源并更新映射，不改 UI、协议或会话逻辑。

## 用户流程

### 首次启动

1. 没有 `style_id` 时显示现有聊天风格选择页。
2. 用户确认后，沿用当前注册流程保存 `style_id`。
3. 没有 `avatar_id` 时显示形象选择页，默认选中现有形象。
4. 用户确认后保存 `avatar_id`，进入聊天页。

如果旧用户已有 `style_id` 但没有 `avatar_id`，直接补显示形象选择页。存储失败沿用现有错误处理，不写入半成品选择。

### 设置

现有右下角设置入口打开“聊天伙伴设置”页。页面包含两个可滚动分区：聊天风格和形象。只有发生变化的分区才调用对应保存逻辑；成功后返回聊天页并提示“已换好，下次聊天时生效”。头像保存只写本地安全存储，不请求网关。

## 数据与边界

### 头像目录

目录至少包含以下 id：

| id | 标题 | 资源路径 |
|---|---|---|
| `default` | 现有形象 | `./avatars/avatar.glb` |
| `cute-girl` | 可爱小女孩 | `./avatars/cute-girl.glb` |
| `cute-boy` | 可爱小男孩 | `./avatars/cute-boy.glb` |
| `young-woman` | 青年美女 | `./avatars/young-woman.glb` |
| `young-man` | 青年俊男 | `./avatars/young-man.glb` |

目录是唯一的产品文案和路径来源。未知 id 不能拼接任意 URL；读取到未知 id 时回退 `default`。

### 本地存储

- key：`avatar_id`
- 值：目录中的 id
- 与 `style_id` 分开读写。
- 不记录对话内容、音频或模型资源正文。

### WebView 配置

配置消息增加 `avatarUrl` 字段。Flutter 只发送目录解析后的路径；WebView 端再次校验相对路径和白名单，拒绝 `http:`、`data:`、`..` 穿越及目录外路径。桌面调试没有 Flutter 配置时继续使用默认模型。

## 失败处理

- 本地存储读失败：显示现有存储错误，不能伪造已保存头像。
- 本地存储写失败：保留当前选择页，显示可恢复错误。
- 头像 id 不认识：使用默认目录项。
- GLB 缺失或加载失败：使用默认模型并发送不含路径或正文的匿名诊断事件；聊天会话仍可启动。
- 当前会话不会因为保存头像而重建、断开或清空状态。

## 测试与验收

- Dart 单元测试：头像目录完整性、未知 id 回退、`avatar_id` 读写、首次补选流程、设置页成功/失败状态。
- TypeScript 单元测试：`avatarUrl` 配置边界校验、允许目录路径、拒绝任意 URL 和路径穿越、缺失模型回退。
- 回归：现有聊天风格选择、身份注册、Mock 会话和声音配置测试继续通过。
- 手工验收：首次启动、旧用户补选、设置页切换、重启后持久化、切换期间当前会话不受影响；资源齐备后逐一确认五个模型实际加载。

## 非目标

- 不修改网关 HTTP/WS 契约和数据库。
- 不让模型根据形象改变人设、声音、记忆或提示词。
- 不在当前会话内热切换模型。
- 不在本任务内制作四个 GLB 美术资源；资源缺口记录为外部输入，功能先用默认模型回退。
